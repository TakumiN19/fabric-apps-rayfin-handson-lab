# Lab 05 — Visuals Pack と洗練された業務 UX デザイン（Linear スタイル × Z の法則・クロスフィルタ）

所要時間: 約 25 分
前提: [Lab 04](04-fabric-data-connectors.md) 完了

Rayfin は堅牢なバックエンドとデータ接続を提供しますが、**「業務現場が毎日使いたくなる画面体験（UX）かどうか」はフロントエンド設計で決まります。**
生成 AI に何も制約を与えず「ダッシュボードを作って」とだけ頼むと、虹色のグラデーション・過剰な影・意味のない円グラフ・優先順位の分からない KPI の羅列になりがちです。

このラボでは、Rayfin の **`graphein-visuals`（Vega-Lite / 宣言的チャート仕様）** パックと、`specs/constitution.md` に定めた **Linear スタイル（抑制された配色）× Z の法則（結論先行の情報配置）** を使い、プロフェッショナルな業務コントロールタワー UI を構築します。

---

## 🎨 本ラボで適用する 3 つの UX 原則

### 1. Z の法則（視線誘導に基づく 2 帯レイアウト）
人の視線は **左上 → 右上 → 左下 → 右下（Z 字）** に動きます。各帯の左端に「結論（今すぐ判断すべき数値・優先キュー）」を置き、右へ「根拠・内訳・アクション実行」を配置します。

```text
┌───────────────────────────────────────────────────────────────────────────────┐
│ Header: Smart Ops Hub              [Live: Fabric] [User: studentX] [Sign out] │
├───────────────────────────────────┬───────────────────────────────────────────┤
│ 【① 左上: 結論 KPI（対基準・状況）】│ 【② 右上: 根拠・構造比較チャート】         │
│  ・要補充 SKU 数: 72 件 [要対応]  │  ・リージョン別 欠品リスク金額（横棒・細身）│
│  ・欠品リスク額: ¥6,143,332       │    Chubu ¥3.10M / Kansai ¥1.37M ...       │
│  ・総在庫数:     22,001 個        │    （クリックで下段キューをクロスフィルタ） │
│  ・平均在庫日数: 7.92 日          │  ・商品カテゴリ別 要補充件数（単色濃淡）   │
├───────────────────────────────────┴───┬───────────────────────────────────────┤
│ 【③ 左下: 優先アクションキュー】      │ 【④ 右下: 即時アクション＆点検メモ】    │
│  Low-Stock Queue (リスク金額順)       │  選択中: ST-005 × SKU-120              │
│  [検索] [地域フィルタ解除]            │  ・推奨発注数: 360 個 → [発注を確定]   │
│  ▶ ST-005 | SKU-120 | 残1.25日 | ¥1.44M│  ・店舗点検メモ (StoreNote) 登録・一覧 │
│    ST-005 | SKU-105 | 残0.94日 | ¥0.72M│  ・直近の補充発注履歴 (RestockOrders)  │
└───────────────────────────────────────┴───────────────────────────────────────┘
```

### 2. Linear.app スタイルの抑制されたデザインシステム
- **アクセントカラーはアプリ全体で 1 色のみ**（例: `#2563EB` またはダークテーマ時 `#4C8DFF`）。
- **信号色はステータス表現専用**: 赤（緊急・在庫日数 < 2.0 日）、琥珀（安全在庫割れ）、緑（正常・発注済）は小さなドットやバッジにのみ使い、グラフの塗りつぶし全面には使わない。
- **カテゴリ比較は単一色相の濃淡ランプ**、棒グラフは細身（thin bars）、**グラデーション・発光（glow）・強いドロップシャドウは禁止**。
- 数値はすべて `tabular-nums`（または等幅フォント）で桁を揃え、コントラスト比は **WCAG AA（4.5:1 以上）** を満たす。

### 3. データ粒度（Grain）への誠実さ
- リージョン別バーをクリックしたときは、実データにリージョン属性を持つ要補充キューと KPI を正確に再計算・絞り込みます（例: `Chubu` 選択時は `20 件 / ¥3,104,568`）。存在しない軸の擬似フィルタは作りません。

## 5-1. `graphein-visuals` スキルを確認し、コントロールタワー画面を実装する

Universal App には、宣言的なチャート仕様（`<Chart spec={...} />` / Vega-Lite ベース）を扱う **`graphein-visuals`** スキル（または `npm run pack:add -- analytics` のビジュアルキット）が用意されています。

> 🗣️ **プロンプト**
> ```text
> `specs/constitution.md` と `specs/spec.md` の UX 原則（Linear スタイル × Z の法則）およびプロジェクト内の `graphein-visuals` スキルに従って、
> smart-ops-hub のメイン画面をプロフェッショナルな在庫＆補充コントロールタワーに刷新して。
>
> 要件:
> 1. 配色は単一ブランドアクセント（`#2563EB`、ダーク切替対応なら `#4C8DFF`）、1px ボーダー基調、グラデーション・過度な影なし、数値はすべて `tabular-nums` 桁揃えにする
> 2. 上段左（結論）: 4枚のコンパクト KPI ストリップ（要補充 SKU 数・欠品リスク金額・総在庫数・平均在庫日数）
> 3. 上段右（根拠）:
>    - リージョン別（Chubu / Kansai / Kanto / Kyushu）の欠品リスク金額 横棒チャート（バーをクリックすると選択リージョンでトグル絞り込みできるクロスフィルタ対応）
>    - カテゴリ別の要補充 SKU 件数（単色相の濃淡バー）
> 4. 下段左（優先キュー）: 安全在庫割れアイテム一覧（検索・リージョン絞り込み連動・行クリックで選択）。在庫日数 2.0 日未満にのみ赤ステータスドットを表示
> 5. 下段右（アクションパネル）: 選択中の店舗×SKU の詳細表示、推奨発注数（`suggested_reorder_qty`）がプリセットされた補充発注フォーム、およびその店舗の `StoreNote` 登録・一覧タブ
> ```

🤖 **Copilot の動き**
- `.agents/skills/graphein-visuals/SKILL.md` を参照し、宣言的なチャートコンポーネント（または Recharts と組み合わせたアクセシブルな SVG チャート）を実装します。
- CSS カスタムプロパティ（テーマトークン）と Tailwind v4 クラスで統一感のある Linear 風スタイルを構築します。
- `npm run lint`（ある場合）・`npm test`・`npm run build` をすべて通します。

✅ **期待する結果**
型チェックと本番ビルドがエラーなく完了する。

## 5-2. デプロイしてクロスフィルタと Write-back の連動を確認する

> 🗣️ **プロンプト**
> ```text
> 更新した smart-ops-hub のフロントエンドを Fabric にデプロイして（`rayfin up staticapp deploy` または `rayfin up`）、動作確認ポイントを教えて。
> ```

🤖 **Copilot の動き**
- バックエンドスキーマに変更がない場合は高速な `npx rayfin up staticapp deploy`（約 30〜60 秒）、全体更新が必要な場合は `npx rayfin up --workspace-id "$WS_ID" --yes` を実行します。

**Fabric ポータルで操作確認しましょう:**
1. **Z の法則の確認**: 画面を開いた瞬間に左上の結論（要補充 `72 件`・欠品リスク `¥6,143,332`）が目に入り、右上のチャートで **`Chubu`（¥3,104,568）が最大リスク地域** であることが一目で分かる。
2. **クロスフィルタの確認**: 右上の横棒チャートで `Chubu` をクリックすると、左下の要補充キューが **`20 件`** に絞り込まれ、先頭に `ST-005（名古屋栄セントラル）× SKU-120` が表示される。もう一度クリックするとフィルタが解除される。
3. **シームレスなアクション実行**: 行をクリックすると右下のアクションドロワーに `ST-005 × SKU-120` と推奨発注数 **`360`** が自動セットされ、そのまま 1 クリックで補充発注・現場メモを登録できる。

## 🔍 （参考）Universal App の `analytics` パック（Sujata 氏紹介の Data App テンプレート）について

FabCon / Build で Sujata Narayana 氏が紹介した **Data App テンプレート**（Universal App では `npm run pack:add -- analytics` で導入可能）は、次の特徴を持つ「セマンティックモデル分析特化キット」です：
- `@microsoft/rayfin-semantic-model-pack` ＋ `@microsoft/rayfin-visuals-pack`（Vega-Lite ベースの AI フレンドリーな視覚化パッケージ）＋ DAX / デザイン用エージェントスキルを一括導入します。
- 注意点として、`analytics` パック単体は既定で `services.data.enabled: false`（アプリ専用 SQL DB なしの読み取り専用 BI アプリ構成）にセットします。
- 本ハンズオンの `smart-ops-hub` のように **「セマンティックモデル分析 ＋ アプリ SQL DB への業務書き込み（Write-back）」の両方を行う場合** は、Lab 03 の `data` サービスを有効にしたまま `fabric-semanticmodel` コネクタと `graphein-visuals` を組み合わせる構成（`Caldova Reorder` と同じ構成）がベストプラクティスです。
